# Поддержка платформ

## Windows-форк

Этот форк предназначен для нативного запуска сервера, host-daemon и веб-интерфейса на Windows x64 без WSL. Точка входа — `scripts/windows/bb.ps1`. Установка, CLI, провайдеры и обновление описаны в [инструкции Windows](../README.windows.md).

Нужны PowerShell 7, Git, Node.js не ниже 22.19 и pnpm 9.15.0. Для этой сборки используется Windows x64; проверенная версия Node.js — 24.13.1.

Установщик Electron, подписанные бинарные релизы и автоматический запуск при входе в Windows пока не входят в поставку. Пакет `bb-app` в npm и релизы upstream выпускаются отдельно: команда `npx bb-app` не устанавливает этот Windows-форк.

## Другие платформы и клиенты

Исходная кодовая база содержит поддержку macOS, Linux, WSL2 и мобильного клиента. Их исходники сохранены для совместимости с upstream. Инструкции для мобильной разработки находятся в [apps/mobile](../apps/mobile/README.md).

В Windows-форке используйте PowerShell и нативные Windows-программы. Не смешивайте в одном экземпляре Windows-процессы и установленные внутри WSL провайдеры.

## Конфигурация экземпляра

По умолчанию сервер слушает `127.0.0.1:38886`, host-daemon — порт `38887`, данные находятся в `%LOCALAPPDATA%\BBWindows`. Параметры `-DataDir`, `-ServerPort` и `-DaemonPort` задают отдельный экземпляр. CLI должен получать соответствующие `BB_SERVER_URL` и `BB_HOST_DAEMON_PORT`.

`-Lan` включает прослушивание всех IPv4-интерфейсов сервером. Авторизацию, TLS и брандмауэр этот параметр не настраивает. Локальный доступ остаётся значением по умолчанию.

Общие значения режимов разработки и эксплуатации определяет `@bb/config`. Windows-лаунчер явно передаёт параметры экземпляра дочерним процессам; переменные окружения не должны случайно направлять CLI в другой экземпляр.

## Нативные зависимости

Зависимости с нативными модулями, например `better-sqlite3` и `@parcel/watcher`, устанавливаются для конкретной ОС и версии Node. Не переносите `node_modules` с другой платформы или архитектуры.

После смены Node повторите установку на остановленном экземпляре. Если готового бинарного пакета нет, потребуются инструменты сборки C++ для Windows и Python. Не отключайте необходимые установочные сценарии зависимостей.

Для переносимого кода используются `cross-env`, `rimraf`, `cross-spawn` и обёртка над `open`. Операции с путями и файлами выполняются стандартными `node:path` и `fs/promises`.

## Хуки подготовки и удаления окружения

`.bb-env-setup.sh` и `.bb-env-teardown.sh` требуют POSIX Bash и поддерживаются на macOS, Linux и WSL2. **На нативной Windows эти хуки не поддерживаются.** Альтернативного поддерживаемого механизма `.bb-env-setup.ts` нет.

Копирование по `.worktreeinclude` не запускает shell и работает на Windows. Подробные правила создания, подготовки и удаления рабочих копий приведены в [инструкции worktree](worktrees.md).

## Переводы строк

[.gitattributes](../.gitattributes) закрепляет LF для соответствующих текстовых файлов, включая Windows checkout. Не меняйте окончания строк во всём репозитории ради локальных настроек Git.

## Проверки и CI

Сборку, проверки типов и тесты запускайте через Turbo, чтобы сначала собирались зависимости:

```powershell
pnpm exec turbo run build
pnpm exec turbo run typecheck
pnpm exec turbo run test
pnpm exec turbo run test:windows:lifecycle
```

Для изменений отдельного пакета добавляйте `--filter` с его именем. Проверки, требующие провайдеров, описаны в [Windows README](../README.windows.md#verify).

GitHub Actions публичного репозитория отключены. Перед их включением адаптируйте унаследованные workflow upstream к этому форку. Перед включением CI нужно отдельно проверить разрешения, назначения публикации и добавить подходящий Windows runner.
