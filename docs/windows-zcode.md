# ZCode / GLM на Windows

Провайдер `acp-zcode` отображается как **ZCode** и подключается через плагин ACP providers. Для проверенной связки каталог содержит **GLM-5.3** и **GLM-5.3-Flash**, уровни reasoning — **Low / High / Max**. Во время работы агента не нужны WSL или запущенное окно ZCode Desktop.

## Версии и настройка

- Проверенная связка: ZCode Desktop 3.11.2, поставляемый им CLI 0.16.5.
- Адаптер: [jpalmae/zcode-acp](https://github.com/jpalmae/zcode-acp), коммит `42fe149d4b501469343c01f23ba3801832306d53`.
- Патч: `scripts/patches/zcode-acp-windows.patch`; сборка: `scripts/build-zcode-light.ps1`.
- Личная авторизация остаётся в `.zcode/cli/config.json` внутри каталога пользователя. В Git ключи не добавляются.
- `ZCODE_ACP_ZCODE_PATH` задаёт путь к нативному CLI, `ZCODE_ACP_CONFIG_PATH` — к личной конфигурации, `ZCODE_ACP_MODEL` — исходную модель.

[Команды установки, сборки и регистрации агента](../README.windows.md#zcode--glm).

Путь установки может отличаться. Получайте его из своего компьютера; не копируйте чужие пути или конфигурацию авторизации. Конфигурация провайдера передаётся нативному процессу через stdin при создании и восстановлении сессии.

## Модель и reasoning

Выбор модели использует нативный `session/setModel`, reasoning — `session/setThoughtLevel`. Через ACP возвращаются проверенные нативные настройки. Они применяются перед каждым новым сообщением, а также после восстановления runtime и отмены. Сначала меняется модель, затем reasoning; ошибка настройки не позволяет молча отправить запрос со старой моделью.

В интерфейсе выберите **ZCode**, нужную модель и уровень reasoning. Эквивалентные команды:

```powershell
bb provider models acp-zcode --environment <environment-id> --json
bb thread update <thread-id> --model zai/GLM-5.3-Flash --reasoning-level max
```

Подставьте идентификаторы своей среды и треда. Для старого треда с `acp-default` один раз выберите конкретную модель. Те же операции доступны через существующие методы SDK для каталога моделей и обновления треда.

Адаптер удаляет только точный повтор префикса инструкций последнего пользовательского сообщения. Изменённые инструкции сохраняются; при ошибке чтения истории сохраняется весь запрос. Существующая история не переписывается. Диагностический `model-io` может сохранять полные снимки контекста — не публикуйте такие логи.

## Совместимость с Windows

Патч исправляет пути запуска и скрытые дочерние процессы, использует постоянные нативные ID сессий, передаёт настройки runtime и режима, поддерживает новую MCP-схему и повторную передачу MCP при восстановлении. Ожидающий запрос регистрируется до подтверждения отправки. Передача изображений через ACP включена; неподдерживаемая возможность embedded-input отключена.

## Изображения

Выберите **GLM-5.3-Flash** и вставьте или прикрепите изображение в поле сообщения. Передаётся содержимое изображения, а не строка с локальным путём. **GLM-5.3** поддерживает только текст: при передаче изображения возвращается явная ошибка без скрытой смены модели.

Поддерживаются PNG, JPEG, WebP и GIF, в том числе сообщения только с изображениями. Ограничения: 10 МиБ на изображение, 20 МиБ и 8 изображений на сообщение. Некорректный base64 и неподдерживаемый MIME отклоняются. Загрузка изображений по внешнему URL, PDF и видео этим механизмом не добавляются.

```powershell
bb thread tell <thread-id> "Опиши изображение" --model zai/GLM-5.3-Flash --image "C:/absolute/path/image.png"
```

Замените путь на свой; для нескольких изображений повторяйте `--image`. Аналогичные вложения доступны через существующий SDK. Успешная передача не гарантирует безошибочное распознавание текста на картинке.

## Отмена и восстановление

В проверенной версии CLI команда `session/stop` подтверждалась, но генерация продолжалась. Поэтому ACP cancel завершает принадлежащее сессии дерево нативных процессов. Следующий запрос восстанавливает ту же сохранённую сессию. Кнопка Stop в bb также освобождает runtime провайдера.

Отмена не откатывает уже выполненные изменения файлов и внешние действия.

## Локальная диагностика

Адаптер добавляет снимки в `bb-status/<native-session-id>.jsonl` рядом с `ZCODE_ACP_CONFIG_PATH`. Они содержат связь с тредом, PID адаптера и CLI, идентификатор создания процесса, время запуска, рабочий каталог, модель, reasoning и состояние хода. Это локальная диагностическая история; не добавляйте её в Git.

Windows PID проверяется вместе с временем создания FILETIME, чтобы переиспользованный PID не считался прежним процессом. Если идентификатор отсутствует или процесс недоступен, состояние — `unverified`. Записанное состояние хода само по себе не доказывает, что процесс работает. Старым сессиям нужен перезапуск, чтобы появились новые отчёты.

MCP-диагностика использует событие `process/mcpTelemetry` с `kind=session_startup` и ID текущей сессии: количество настроенных, подключённых и ошибочных серверов, а также подключённых stdio-процессов. Это сведения о запуске, а не непрерывная проверка всех инструментов. `not_checked` означает, что подходящее событие ещё не получено. После остановки сохраняется прежний результат с временем события.

Глобальный `mcp/list` в CLI 0.16.5 относится к отдельной аренде `protocol-settings` и не описывает подключения рабочей сессии. Диагностика не создаёт дополнительный опрос, не переподключает MCP принудительно и не меняет разрешения. В диагностические снимки не записываются ключи, дампы окружения, сырые MCP-ошибки, URL авторизации и содержимое сообщений.

Личные диагностические probe-скрипты не поставляются в публичной сборке. Не используйте команды из прежних локальных отчётов.

## Пересборка и проверки

Не собирайте поверх работающего `zcode-acp.exe`. Сначала остановите использующие его сессии. Подготовьте закреплённый checkout, примените патч и выполните:

```powershell
pwsh -File scripts/build-zcode-light.ps1
pwsh -File scripts/build-zcode-light.ps1 -Task test
```

Скрипт ограничивает Cargo одной задачей, понижает приоритет процесса и использует отладочный профиль. Для изменений ACP-моста bb:

```powershell
pnpm exec turbo run build --filter=bb-plugin-provider-acp --concurrency=1
```

Для обновления всего установленного Windows-экземпляра используйте [общий порядок остановки, сборки и запуска](../README.windows.md#update-and-integrate-upstream). Не заменяйте отдельные файлы артефактов работающего экземпляра вручную.


## Ограничения

- Экспериментальный адаптер к закрытому протоколу поставщика; это не официальная поддержка ZCode.
- Flash — отдельная модель. Общий переключатель скорости/service tier bb с ней не связан.
- Нативный режим начинается с `build`. Режим Full Access bb пока не сопоставлен с нативным `yolo`; ZCode может запросить подтверждение.
- Перечисление, импорт и ответвление произвольных старых desktop-сессий не проверены.
- Используйте авторизованный нативный CLI, а не прежний OAuth-сценарий адаптера.
- После обновления ZCode повторите проверки модели, reasoning, отмены, восстановления и вложений.
